## 1. AntMaze reproduction (fixed)
- The earlier "AntMaze does not reproduce (1/11)" was a **Windows rendering bug**: on Windows MuJoCo renders through
  glfw, and after the first `World` is closed every `World` created later in the same process renders **black
  frames**. The chunked eval planned tasks 2..N from black images.
- Fix: one process per task — `HJEPA_ONE_CHUNK_PER_PROCESS` in `planning_eval.py` (in `hjepa_changes/`) and
  `experiments/run_ant_eval_isolated.py`. Paper 3-level H-JEPA: **9/13 (69%)** vs paper 73.3 ± 3.5.
- Rule for all scripts: one `World` per Python process.

## 2. Two facts about H-JEPA level 3 that every System-2 design must respect
- **Level-3 macro-actions live on a LayerNorm manifold.** Level 3's `action_encoder` ends in `LayerNorm(4)`; every
  real macro-action has norm 2.033 ± 0.006. Off-manifold actions make F3 predict exaggerated, unreachable steps
  (real step 1.9; Gaussian norm≈1.3 → 5.1; random radius-2.03 direction → 7.9). Map proposals with `a = LN(u)`.
  All System-2 runs before this finding (reservoir v3, VAE generator, CEM, early AIF agents) used off-manifold actions.
- **H-JEPA reaches latent goals only when they are real encodings.** Given the paper goal image only as its level-3
  latent, H-JEPA solves 7/8 paper tasks (`results/antmaze_goalpath/`); F3-imagined or centroid latents are not
  reliably reachable. One level-3 step = 20 env steps; a 3-cell task needs ~300 steps.

- **Tschantz et al. 2020** (`third_party/rl-inference`, MIT): official ensemble / CEM planner / information-gain
  measure; edits = actions through H-JEPA's action LayerNorm, learned reward replaced by goal preference.
  Ensemble trained on 18,750 real level-3 transitions: next-state R² 0.915. Faster when it succeeds; solves task 12
  (H-JEPA fails it); 15-step plan 8/13 vs 9/13.
- Play-to-goal route (agent plays z3 until near the goal, H-JEPA follows the route then finishes): first agent to
  solve task 4; 7/11 when stopped.
- **Fountas et al. 2020** (`third_party/deep-active-inference-mc`, GPL-3.0): adapted (`system2/fountas_z3.py`,
  model next-obs R² 0.82) but dropped — its MCTS needs discrete actions (12 prototypes), level 3 is continuous.
  The official `calculate_G_mean` uses one dropout sample, so its info-gain term is mostly noise.
