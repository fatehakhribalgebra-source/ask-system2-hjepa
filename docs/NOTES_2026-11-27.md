## E0: reproducibility (DESIGN_ANIMAL step E0)

**Cause of the noise.** `locomaze_env.settled_info_from_xy` settles the `xy_neutral` start and goal poses with
`action_space.sample()`, and nothing seeds that action space. The eval file has no `seed`. So every run of the "same"
task starts the ant in a different pose: task 10 took 109 / 310 / 116 steps as-is.

**Fix.** `eval_l3_planner.py --deterministic [--repeat R]`:
- seeds python, numpy and torch with `seed*1000+task`;
- turns off TF32 and makes cudnn and torch deterministic (warn_only);
- seeds every action space in the env wrapper chain with `seed*1000+task+100000*R`.

`--repeat R` picks another settled pose. This turns the start-pose noise into an explicit repeat axis.

**Run.** Seed-42 checkpoint, tasks 0-12, repeats 0, 1, 2, for two planners: the offline RGM map (`rgm_paper`, z3,
k64) and H-JEPA's own gradient planner (`gd`). gd repeat 0 was run twice. The run took 2 h 30 min. Table:
`results/e0_repro/summary.md`.

| planner | rep0 | rep1 | rep2 | mean ± SE | tasks that flip |
|---|---|---|---|---|---|
| RGM (offline map) | 10/13 | 11/13 | 11/13 | **82.1 ± 2.6 %** | 4/13 |
| H-JEPA gd | 8/13 | 6/13 | 8/13 | **56.4 ± 5.1 %** | 10/13 |

- **Same seed and same repeat reproduce the run exactly:** gd rep0 run twice was 13/13 identical in success and steps.
  The RGM probe on task 10 was also identical three times (277 steps, same RGM stats). The GPU work is not a source
  of noise.
- **Board test (flips < 2/13): failed for both planners.** The noise is the start pose, not the code. One settle of
  the ant decides success on 4 of 13 tasks for RGM and on 10 of 13 for gd.
- **Rule from now on:**
  - Report means over repeats only, never per-task wins.
  - Always compare planners on the same `--deterministic --repeat` set (paired).
  - With 13 tasks × 3 repeats, the SE is about 3-5 points. A gap under about 8 points between two variants is not
    a result.
  - Use more repeats, or all 50 tasks, before believing a smaller gap.
- Steps to success also move a lot between repeats (task 10: RGM 277 / 195 / 158). Use success rate, not steps, as
  the main measure.
- The RGM vs gd gap (82 vs 56) is about 26 points, well above the noise. On the earlier 50-task, 3-seed run it was
  76.0 % for RGM vs 73.3 % for the paper's H-JEPA.
- **Why gd scores 56 % here.** The setup is the AntMaze medium stitch tasks 0-12 of `expert_grid_d3_n50`, with the
  seed-42 checkpoint and a 350-step budget. gd reaches goals late: the median solved run takes about 297 steps
  (RGM about 220), and 10 of 22 gd successes take over 300 steps. A slightly worse start pose pushes it past 350,
  which is why 10 of 13 of its tasks flip. On 19 Nov the same 13 tasks as-is gave 9/13 (69 %). 13 tasks is too few
  to tell this apart from the paper.
- **Decision (user): the gd baseline is always the paper score, 73.3 ± 3.5 %.** gd is not rerun as a baseline.

## Step 2: reflex test-time adaptation (AdaJEPA fast loop), default dynamics

`system2/reflex_ttt.py`, `eval_l3_planner.py --ttt --ttt-lr 1e-4`. Before every replan (every 10 env steps) it takes
one Adam step on the latent prediction loss of the last 10 level-1 transitions (and the level-2 ones inside them). Only
the first transformer block of the level-1 and level-2 predictors changes; encoders stay frozen. Learning rate check
on task 10: 1e-5 too small, 1e-3 makes level 2 worse and fails the task, so 1e-4 is used.

Paired with E0 (same tasks 0-12, same 3 start poses, seed 42):

| | RGM | RGM + TTT |
|---|---|---|
| success (mean ± SE over repeats) | 82.1 ± 2.6 % | 76.9 ± 4.4 % |
| tasks that flip between repeats | 4/13 | 8/13 |
| both solved (26 pairs): median steps | 224 | 218 (faster in 14 vs 12, p = 0.85) |
| time to goal, failure = 350 | 251 | 250 |
| held-out prediction error, level 1 | release weights | **−9.6 %** (lower in 38/39 runs) |
| held-out prediction error, level 2 | release weights | **−16.0 %** (lower in 36/39 runs) |

**Reading.** Adaptation works as a world-model update: the reflex predicts its own next states clearly better, before
training on them. On default dynamics it does not change planning: the success gap (5 points) is under the ~8-point
noise floor, and speed is the same. It adds some run-to-run variation (flips 4 → 8). That is expected, because the
release model already fits these dynamics. The test where adaptation should matter is E5 (changed body: mass ×0.5,
damping ×5). Not run yet; JEPA-TTT persistence across tasks and OpTTA's optimism term are not done either.
