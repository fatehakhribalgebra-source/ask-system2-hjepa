··Our model: System 2 over a frozen H-JEPA

H-JEPA stays frozen. Our System 2 is a renormalising generative model (RGM), built the way the "From pixels to planning" paper builds it, but it sees H-JEPA's level-3 latent \(z_3\) instead of pixels. It replaces only H-JEPA's top-level planner. It decides which place to go to next, and H-JEPA's levels 2 and 1 act as the reflex that gets the ant there.

In symbols, with \(c(\cdot)\) mapping a latent to its place and \(N\) the transition counts between items:

\[ s_t = c(z_3) = \arg\min_k \big\|W(z_3-\mu) - m_k\big\|, \qquad \pi = \arg\max_{\text{path}\,\to\,\text{goal},\ \le 16} \textstyle\prod P(u'\mid u), \quad P(u'\mid u) \propto N(u\to u')\ \big[\,\ge \tfrac1{16}\max\,\big], \qquad z_3^* = \text{medoid}(s_{t+1}) \]

Success on 50 tasks × 3 seeds is 76.0 ± 4.2%, against 73.3 ± 3.5% for H-JEPA's own planner (paper). On today's paired runs it also reaches goals sooner (section 05).

01Actions built from the level below parked

In H-JEPA each level-ℓ+1 action is encoded from a run of level-ℓ action embeddings, and the encoder ends in LayerNorm(4). LayerNorm removes the mean and the scale, so every upper action lands on a 2-dimensional shell:

\[ a^{\ell+1} = \mathrm{LN}\!\big(E_\ell(a^\ell_1, a^\ell_2)\big) \;\in\; \Big\{x\in\mathbb R^4 : \textstyle\sum_i x_i = 0,\ \|x\| \approx 2.03\Big\} \cong S^2 \]

The sphere forgets how the action was made: two different pairs of lower moves can give the same point, and nothing records which pairs. The idea is to make the upper action the product of the lower ones. Truncated path signatures do this exactly, because composing two paths multiplies their signatures (Chen's identity), and in log coordinates the product is the Baker–Campbell–Hausdorff series:

\[ S_N(\gamma_1 \ast \gamma_2) = S_N(\gamma_1)\otimes S_N(\gamma_2), \qquad \log\!\big(e^{a_1}e^{a_2}\big) = a_1 + a_2 + \tfrac12[a_1,a_2] + \cdots \]

Then each upper action \(A\) owns a fibre: all the ways of making it from below.

\[ F(A) = \{(a_1,a_2) : a_1 \star a_2 = A\} \]

03E0: where the noise comes from done

The same task, run three times as it was, took 109, 310 and 116 steps. The planner was not the cause. Before an episode starts, the env drops the ant at its start and goal positions and lets it settle by taking random actions (locomaze_env.settled_info_from_xy). Nothing seeds that random source, so each run starts from a different pose \(\xi\).

So the start pose becomes an explicit axis we control. For task \(t\) and repeat \(r\):

\[ s_{t,r} = 1000\cdot\text{seed} + t + 100\,000\cdot r, \qquad \xi_{t,r} = \mathrm{settle}(s_{t,r}), \qquad y_{t,r} = \mathbb 1\big[\text{goal reached within } 350 \text{ steps from } \xi_{t,r}\big] \]

Running the same \((t, r)\) twice now gives the same run: H-JEPA's planner on repeat 0 matched itself on 13 of 13 tasks, step for step. The GPU adds no noise.

04E0: how much the start pose matters

Seed-42 checkpoint, tasks 0–12, repeats \(r = 0, 1, 2\), two planners on the same poses: RGM (ours) and gd, H-JEPA's gradient planner. A task flips if its outcome depends on the repeat:

\[ \phi_t = \mathbb 1\big[\exists\, r, r' : y_{t,r} \neq y_{t,r'}\big], \qquad \text{board test: } \textstyle\sum_t \phi_t < 2 \]

Success per repeat is \(\hat p_r = \tfrac1{13}\sum_t y_{t,r}\). We report the mean over repeats with its standard error:

\[ \bar p = \frac1R\sum_{r} \hat p_r, \qquad \mathrm{SE} = \frac{\operatorname{sd}(\hat p_0,\hat p_1,\hat p_2)}{\sqrt R} \]

How small a gap can 13 tasks × 3 repeats detect? Treat each run as a coin with \(p \approx 0.6\):

\[ \sqrt{\frac{p(1-p)}{13\cdot 3}} = \sqrt{\frac{0.24}{39}} \approx 0.078 \;\Rightarrow\; \text{gaps under about 8 points are noise} \]

Rules from now on: report means over repeats, never per-task wins; compare planners on the same repeats; for success, cite the paper's 73.3% for gd.

05Speed: ours gets there sooner

The paper reports only success, so speed is measured on our own paired runs. A pair is the same task and the same repeat (the same start pose) run by both planners. For the 21 pairs where both reach the goal, the difference in steps is

\[ d_i = T^{\text{gd}}_i - T^{\text{RGM}}_i, \qquad \operatorname{median}(d) = +46 \text{ steps} \approx 2\text{–}3 \text{ level-3 moves (20 steps each)} \]

Is 15 vs 5 more than luck? Under a fair coin (sign test, the tie dropped):

\[ p = 2\sum_{k=0}^{5}\binom{20}{k}2^{-20} = \frac{2\cdot 21\,700}{1\,048\,576} \approx 0.041 \]

To count failures as well, use a capped time to goal over all 39 pairs, where a failure counts as the full budget:

\[ \tilde T = \begin{cases} T & \text{solved} \\ 350 & \text{failed} \end{cases} \qquad \overline{\tilde T}^{\,\text{gd}} = 312,\quad \overline{\tilde T}^{\,\text{RGM}} = 251,\quad \Delta = 60 \pm 12 \text{ (SE)} \]

This covers 13 tasks and one model seed. Claiming it in the thesis needs a paired run of both planners on all 50 tasks × 3 seeds (about 7–8 h). That is on hold.
